# Potato Price Forecasting -- Does Model Complexity Help?

Reviewer-safe, reproducible pipeline extending Guo, Guo & Gu (2025),
*"ELinear: ensemble linear model for stock prediction"* (Neural Computing and
Applications, 37, 15079-15093, doi:10.1007/s00521-025-11280-9) to Agmarknet
daily potato price data for two Uttar Pradesh markets, Agra and Farrukhabad
(Jan 2010 - Jul 2025). Companion code for the manuscript *"Does Model
Complexity Improve Potato Price Forecasting? A Multi-Horizon Comparative
Analysis"* (submitted to *Potato Research*, Springer).

## Run order
1. Drop your Agmarknet Excel export(s) at `data/agra_potato_raw.xlsx` and
   `data/farrukhabad_potato_raw.xlsx` (Date, Price columns).
2. Run notebooks **01 -> 07** in order. Each writes artifacts that the next
   notebook consumes -- no notebook should be run out of order on a first pass.
   Notebook 06 is the manuscript-facing filter (drops ARIMA/Seasonal-Naive);
   Notebook 07 is a diagnostic/repair pass, run once results from 04 are in.
3. On Colab: each notebook's first code cell mounts Google Drive and installs
   the extra packages it needs. Set `PROJECT_ROOT` in that cell if you
   uploaded the project folder somewhere other than `MyDrive/potato_pipeline`.

## Models compared
Nine models make up the final manuscript comparison (ARIMA and Seasonal-Naive
were run for completeness in Notebook 05 but are excluded from the
manuscript per a fair, equal-footing comparison across model families):

| Tier | Models | Implementation |
|---|---|---|
| Naive baseline | Persistence (Naive) | hand-written, deterministic |
| Deep learning benchmarks | LSTM, TCN, N-BEATS, DLinear, NLinear, PatchTST, iTransformer | **NeuralForecast** (Nixtla) |
| Proposed | **ELinear** | from-scratch PyTorch (`src/elinear_model.py`) |

ARIMA and Seasonal-Naive remain available in `src/` and Notebooks 01-05 for
anyone who wants the full extended comparison.

## The fairness/reviewer-safety commitment

Every model in the comparison -- **ELinear and all seven NeuralForecast
benchmarks alike** -- is evaluated through one shared, auditable harness
(`src/cv_utils.py`):

- **Identical CV procedure**: `cv_score_generic()` + `evaluate_walk_forward()`
  run the same rolling-origin, walk-forward evaluation for every model,
  regardless of which library implements the underlying architecture.
- **Identical trial budget**: every deep-learning model gets the same
  `N_TRIALS` Bayesian-optimization search (Notebook 02) -- no model receives
  a larger search budget than another.
- **Identical CV folds, identical `seq_len` search grid, identical Optuna
  sampler seed** across every model's tuning study.
- **Identical seed protocol**: every model is trained across the same 5
  seeds on the same tuning pool (Notebook 03).
- **Identical test windows**: final test predictions are generated by the
  SAME `evaluate_walk_forward()` call for every model, guaranteeing the
  Diebold-Mariano test's paired-error assumption holds (predictions are
  compared at exactly the same target dates across models) -- verified
  programmatically (`np.allclose(trues_model_a, trues_model_b)`) before
  trusting any DM result.
- **Identical metric computation**: every model's predictions are scored by
  `src/metrics.py`, never a library's self-reported training/validation loss.
- **Single fit, no leakage**: every model is fit once on the tuning pool and
  never updated using validation- or test-period data.

ELinear is deliberately implemented from scratch rather than squeezed into
NeuralForecast's `BaseModel`/Lightning training loop, because its training
algorithm (Algorithm 1, mutual learning -- three sequential phases with
different loss targets) is non-standard and is the paper's actual
contribution. Routing it through a third-party framework's abstraction would
make its training procedure less auditable, not more convenient. ARIMA is
similarly a documented, deliberate exception to the Optuna-trial-budget
protocol (see Notebook 02) -- order selection via `auto_arima`'s AICc
stepwise search is the standard-of-record method (Hyndman & Khandakar 2008)
and is not a "hyperparameter search" in the same sense as a neural network's.

## Key methodological decisions and their literature basis

| Decision | Choice | Reference |
|---|---|---|
| Missing-data imputation | Kalman smoothing on a structural time series model (validated empirically against linear interpolation and STL-based seasonal-split imputation before being adopted) | Moritz & Bartz-Beielstein (2017); Moritz et al. (2015); Durbin & Koopman (2012); Cleveland et al. (1990) |
| Train/validation splitting | Rolling-origin (walk-forward), expanding window, 5 folds | Tashman (2000); Bergmeir & Benitez (2012); Hyndman & Athanasopoulos, *FPP3* Ch. 5.10 |
| Final test holdout | Last 15% of the series (chronological), touched only once, after all tuning | standard practice to prevent tuning-on-test leakage |
| Hyperparameter search | Bayesian optimization (Optuna, TPE sampler), 20-30 trials per model x horizon | Bergstra & Bengio (2012); Akiba et al. (2019) |
| ARIMA order selection | Stepwise AICc search (`pmdarima.auto_arima`), NOT included in the Optuna sweep; annual seasonality handled via Fourier exogenous regressors rather than raw seasonal ARIMA (m=365 is intractable) | Hyndman & Khandakar (2008); Hyndman & Athanasopoulos, *FPP3* Ch. 10 |
| Repeated runs | 5 random seeds per deep-learning model config, mean +/- std reported | standard variance-reporting practice for DL benchmarks |
| Forecast horizons | 1, 7, 14, 30 days | short-term (operational) through one-month (seasonal-cycle-relevant) |
| Significance testing | Diebold-Mariano test with Harvey-Leybourne-Newbold small-sample correction, Holm-Bonferroni correction across the multiple pairwise comparisons per horizon | Diebold & Mariano (1995); Harvey, Leybourne & Newbold (1997); Holm (1979) |
| Metrics | MSE, RMSE, MAE, MAPE, sMAPE, directional accuracy; PAE (practical application efficiency) reported where high/low price data is available | sMAPE included because MAPE is unstable near low prices; PAE follows Guo et al. (2025) |
| DLinear/NLinear/PatchTST/iTransformer/LSTM/TCN/N-BEATS implementations | NeuralForecast (Nixtla) reference implementations, all wired through one shared fit/predict interface | ensures benchmarking against maintained, well-tested implementations while guaranteeing identical CV/seed/metric treatment vs. ELinear |

## Notes for reviewers
- The final 15% of the chronological series is never touched during
  imputation validation, hyperparameter tuning, or model training -- only in
  Notebook 04, once, for final scoring.
- All non-deterministic models are trained across 5 seeds; reported metrics
  are mean +/- std, not single-run figures.
- Significance claims (Notebook 04/05) are Holm-Bonferroni corrected across
  the family of pairwise comparisons run per horizon, avoiding inflated
  false-positive rates from uncorrected multiple testing.
